## What's in this template

<div class="grid cards" markdown>

-   :material-cog-outline: **CMake + CTest + googletest**

    ---

    A `utility` library, a `calculator` library (fully unit-tested infix/postfix expression parsing) and a
    `calculatorapp` command-line demo, wired up with CMake and CTest. Builds on Windows (Visual Studio or
    Ninja + MinGW, auto-detected) and Linux/WSL (Ninja + GCC).

    [:octicons-arrow-right-24: Install & first build](guide/install.en.md)

-   :material-file-document-multiple-outline: **Every report, two ways**

    ---

    Unit-test results, code coverage and documentation coverage are each generated **twice**: once with
    [ReportGenerator](https://github.com/danielpalme/ReportGenerator) and once with the ecosystem's own
    native/older tool (OpenCppCoverage, lcov `genhtml`, gcovr) - so you can see how they differ.

    [:octicons-arrow-right-24: Which report is which?](reports.md)

-   :material-file-tree-outline: **API docs (Doxygen)**

    ---

    Full API documentation for the library and for the test sources themselves, generated by Doxygen on
    both Windows and Linux, with graceful fallback if Graphviz/PlantUML are not installed.

    [:octicons-arrow-right-24: Browse the Windows API docs](reports/doxygen-lib-win.md)

-   :material-web: **This site, from scratch**

    ---

    Built with MkDocs Material as a best-practice example: every HTML report gets its own page in a styled,
    responsive `<iframe>`, served locally over a tiny HTTP server and deployed automatically to GitHub
    Pages on every push to `main`.

    [:octicons-arrow-right-24: How this site embeds reports](guide/reports-in-site.en.md)

-   :material-source-branch: **From topic to your own project**

    ---

    A worked, step-by-step walkthrough that takes a project topic from the course project guide and turns
    this sample into your own project: renamed targets, your own modules, tests written first.

    [:octicons-arrow-right-24: Topic to project guide](guide/topic-to-project.en.md)

-   :material-lifebuoy: **Troubleshooting, from real errors**

    ---

    A table of real error messages hit while building this exact template (missing submodule, wrong CMake
    generator, `JAVA_HOME`-style PATH issues, Google Drive `desktop.ini`, antivirus locks...) and the exact
    fix for each.

    [:octicons-arrow-right-24: Troubleshooting](guide/troubleshooting.en.md)

</div>

## Requirements at a glance

- CMake >= 3.16 (matches the googletest submodule's own minimum; tested with a current CMake on Windows and
  Linux/WSL)
- C++ standard: 17 by default (GoogleTest 1.15+ requires it)
- GoogleTest (git submodule, pinned to a tagged release - run `0-init-submodules.bat` / `.sh`)
- **Windows**: Visual Studio 2022 Community (Desktop development with C++), *or* Ninja + MinGW-w64 GCC -
  the build scripts auto-detect which one you have
- **Linux/WSL**: Ninja + GCC (the build script picks a GCC version with a matching `gcov` automatically)

Full walkthrough with copy-paste commands and expected output: **[Install (EN)](guide/install.en.md)** /
**[Kurulum (TR)](guide/install.tr.md)**.

## Build it yourself

```bash
# Windows (cmd.exe)
7-build-app-windows.bat

# Linux / WSL
./7-build-app-linux.sh

# Open the site locally (starts a tiny HTTP server - reports use <iframe>
# and most browsers block those from a plain file:// path)
9-open-site.bat   # or ./9-open-site.sh
```

Each full build takes roughly 10-20 minutes and produces, under `docs/` and `site/`: Doxygen API docs,
every unit-test/coverage/documentation-coverage report (both families), and this site. See
**[daily workflow](guide/daily-workflow.en.md)** for the shorter day-to-day loop and
**[private repositories & releases](guide/releases.en.md)** for how the same outputs ship as a GitHub
Release (works on GitHub Free, even for a private student repository).
