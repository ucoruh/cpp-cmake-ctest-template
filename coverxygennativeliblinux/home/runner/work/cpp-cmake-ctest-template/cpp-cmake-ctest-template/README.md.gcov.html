      11              : ## Overview
      12              : 
      13              : This project is a C/C++ course-project template: a small `utility` library, a `calculator` library
      14              : (with unit-tested infix/postfix expression parsing), a `calculatorapp` command-line demo, and a
      15              : googletest suite, wired up with CMake + CTest. It generates two independent HTML reports for every
      16              : report family (a third-party one via [ReportGenerator](https://github.com/danielpalme/ReportGenerator)
      17              : and the ecosystem's native/older tool), Doxygen API documentation, and a site that links all of them.
      18              : See [docs/reports.md](docs/reports.md) ("Which report is which?") once you have built it.

      33              : ## Requirements
      34              : 
      35              : - CMake >= 3.16 (matches the googletest submodule's own `cmake_minimum_required`; tested with 3.31 on
      36              :   Windows, 4.2 on WSL Ubuntu 20.04, and current CMake on GitHub Actions' runners)
      37              : - C++ standard: 17 by default (GoogleTest 1.15+ requires it); override with
      38              :   `-DCMAKE_CXX_STANDARD=...` if you need to test against an older standard
      39              : - GoogleTest (git submodule, pinned to v1.18.0 - run `0-init-submodules.bat`/`.sh`)
      40              : - **Windows**: Visual Studio 2022 Community (Desktop development with C++), *or* Ninja + MinGW-w64
      41              :   GCC - the build scripts auto-detect which one you have (`detect-generator.bat`); no specific
      42              :   Visual Studio version is required.
      43              : - **Linux/WSL**: Ninja + GCC (the build script picks a GCC version with a matching `gcov`
      44              :   automatically, see [docs/guide/troubleshooting.en.md](docs/guide/troubleshooting.en.md))

     160              : ### Github Actions
     161              : 
     162              : Three workflows under `.github/workflows/`:
     163              : 
     164              : - `cpp.yml` - builds and tests (CMake configure + build Release + `ctest`) on every push and pull
     165              :   request, on Windows and Ubuntu - intentionally lean, no report generation, so it stays fast and does
     166              :   not use many Actions minutes.
     167              : - `pages.yml` - on push to `main` (and manually): builds the full report+site pipeline on both
     168              :   Windows and Ubuntu runners, merges both platforms' reports into one site, and deploys it to the
     169              :   `gh-pages` branch (GitHub Pages). On a **private** repository this step is skipped unless the
     170              :   repository variable `PAGES_ON_PRIVATE` is `true` (GitHub Pages needs GitHub Pro/Team, e.g. via the
     171              :   Student Developer Pack) - see [docs/guide/releases.en.md](docs/guide/releases.en.md).
     172              : - `release.yml` - on a `v*` tag push (or manually): builds everything on both platforms and publishes
     173              :   a GitHub Release with every asset (Windows + Linux binaries, all reports, API docs, `site.zip`).
     174              :   Prefer the local `10-release.bat`/`.sh` script day to day; it does the same thing without using any
     175              :   Actions minutes.
